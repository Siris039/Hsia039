# DAVID TAO · 你是哪一种陶喆音乐人格？

以陶喆八张专辑为基础的音乐人格测试。纯静态站点，无后端、无依赖、无付费服务，纯靠 GitHub Pages 托管。

🔗 在线地址：`https://<你的 GitHub 用户名>.github.io/Hsia039/`

> 这不是粉丝知识问答，也不是按「你最喜欢哪首歌」分配结果。它通过二十道关于音乐、情绪、关系与现实的题目，把你放回 1997—2013 的八张唱片里去比对。

## 二、本地运行

任意一种方式：

```bash
# 方式一：Python
cd david-tao-personality
python -m http.server 8000

# 方式二：Node
npx serve .
```

然后打开 http://localhost:8000

> **可以直接双击 `index.html` 打开**，本站没有任何外部依赖。
> 唯一限制：用 `file://` 打开时，「复制结果链接」复制出来的是你电脑上的本地路径，
> 发给朋友打不开（页面会提示这一点）。想分享给别人，部署到 GitHub Pages 即可。

## 三、部署到 GitHub Pages（全程点鼠标，不需要敲命令）

1. 打开 https://github.com/new ，仓库名填 `Hsia039`，选 **Public**，勾选
   **Add a README file**，点 **Create repository**。
2. 仓库建好后，点页面上那个蓝色链接 **uploading an existing file**。
3. 把本地整个 `Hsia039` 文件夹拖进虚线框（注意不要拖里面的文件，拖外面的文件夹本身），
   等文件列表出来后点底部的绿色按钮 **Commit changes**。
4. 点仓库顶部的 **Settings** → 左侧 **Pages**。
5. **Source** 选 `Deploy from a branch`，**Branch** 选 `main`、目录选 `/ (root)`，点 **Save**。
6. 等 1–2 分钟，访问 `https://<你的 GitHub 用户名>.github.io/Hsia039/`。

链接形式与参考站（subway814.github.io/qfti/）一致。之后改动文件再 Commit，约 1 分钟自动生效。

> 命令行版本：`git init` → `git add .` → `git commit -m "init"` →
> `git remote add origin https://github.com/<用户名>/Hsia039.git` → `git push -u origin main`。

## 四、修改指南

### 4.0 界面上的三处「产品决策」（改动前先看这里）

**① 保存海报按钮不真的导出图片。**
点下去只弹提示「自行截图保存吧~」。原因是跨浏览器、跨设备（尤其是手机端和 `file://`）
下载 Canvas 导出的 PNG 成功率不稳定，让用户截屏反而更可靠。
`js/poster.js` 的完整绘制代码保留着，**想恢复导出**：把 `js/app.js` 里
`#poster-btn` 的点击事件换回 `POSTER.download(album, persona, result)` 即可。

**② 「建议聆听」改叫「你可能爱听」。** 更口语，也更像一个推荐而不是作业。

**③ 答题页的题号写成 `TRACK 03 / 20`。** 配合封面大唱片和沟槽质感的进度条，
加一点唱片语境，但不改动整体的深色版式。

### 4.0b 封面解锁机制（为什么有的唱片名字是 ???）

这是本站的核心悬念设计：**人格名是答案，音乐不是。**

- 封面八格，初始全部显示 `? ? ?`，只能点开看这张唱片的音乐事实
- 测出结果 → 该唱片解锁 → 封面那一格亮出人格名，并用这张专辑自己的颜色描边，
  再点就直接进它的结果页
- 双重人格的第二张也算解锁（它的名字已经出现在你的结果页里）；「你的反面」不算

状态存在 `localStorage`（键名 `dt-persona-unlocked`），另有内存兜底：
即便浏览器禁用存储，**本次会话内**解锁依然有效。
注意 `file://` 直接打开时，部分浏览器不允许持久化，关掉网页再开可能回到未解锁状态；
部署到 GitHub Pages 后没有这个问题。

如需彻底关掉悬念（让八个人格名一上来全部显示），删掉 `js/app.js` 里
`renderIntro` 的 `known ? ... : '? ? ?'` 判断即可。

### 4.1 改人格文案 → `content/personalities.js`

每个专辑 id 对应一段文案，字段含义：

| 字段 | 出现在结果页哪里 | 建议字数 |
|---|---|---|
| `name` / `en` | 结果页大标题 | 3–6 字 |
| `tagline` | 大标题下的一句话画像 | 40–60 字 |
| `traits` | 「核心性格」 | 3–4 条，每条标题 + 一句展开 |
| `analysis` | 「为什么是这张唱片」 | 300–400 字，必须落到具体曲目 |
| `debate` | 「另一种声音」 | 保留争议，不要写成夸奖 |
| `songs` | 「你可能爱听」 | 3–5 首，`why` 要回答「为什么这首歌代表这种人格」 |
| `closing` | 页面结尾大字 | 一句话 |

**已从结果页裁掉的字段**（数据仍保留在文件里，改不影响运行，缺了也只会提示不会报错）：
`strengths`、`blindspots`、`love`、`people`、`reality`。
如果哪天想把「优势与盲区」「面对生活」加回来，在 `js/app.js` 的 `renderResult` 里补一个 `block(...)` 即可。

**安全写法**：文字一律放单引号里；英文撇号要写成 `I\'m`（或用全角 `’`）；每对中括号、花括号之间的逗号不要删。改完跑 `node tools/check.js`，它会直接告诉你缺了哪个字段。

### 4.2 改专辑事实 → `content/albums.js`

`lineup` 里的曲目名会被自检脚本用来核对推荐曲是否真实存在。如果新增了某首推荐曲，记得同步加进 `lineup`，否则检查会报警（这是防写错歌名的保护，不是报错）。

### 4.3 改深度解读 → `content/deep-analysis.js`

按「曲名 → 解读」存放。**曲名必须与 `personalities.js` 里 `songs[].name` 逐字一致**，包括英文冒号、空格和括号（例如 `飞机场的10:30` 用半角冒号）。不一致时弹窗会显示「暂无详细解读」，`check.js` 也会报出具体是哪一首。

写作要求：落到具体可听的内容——编制、节奏、曲式、唱腔、歌词写法。不写「很好听」这类无信息量的判断；涉及评价时区分事实与解读。

### 4.4 改彩蛋 → `content/blindbox.js`

每个专辑 id 一枚，含 `title`（曲名）/ `from`（出处）/ `desc`（这首歌是什么）/ `note`（什么时候听）/ `lyric`（**只在有确切把握时填，否则留 `''`，界面会自动隐藏**）/ `persona`（送给谁）。

规则：彩蛋曲目必须是该专辑里**不在结果页推荐列表**中的遗珠，否则等于没多给一首——`check.js` 会检查这一点。

### 4.5 改题目 → `content/questions.js`

```js
{
  no: 4, dim: '冲突反应', weight: 1.2,
  text: '被人当众误解的时候，你的第一反应更接近？',
  options: [
    { label: '当场说清楚，气氛难看也认了', p: 'op2009', s: 'dt1997' },
    ...
  ]
}
```

- `p` = 该选项主要贡献给哪张专辑，`s` = 次要贡献
- 取值只能是八个 id：`dt1997` `ok1999` `bt2002` `us2003` `tp2005` `be2006` `op2009` `hg2013`
- `weight` 越高，这道题对结果的影响越大

**出题三条红线**：选项不能有明显好坏之分；不要问「你最喜欢哪张专辑」；`p` 的总量要八维均衡（理想每十个一次，`check.js` 会盯着）。

### 4.6 调结果分布 → `js/scoring.js`

| 参数 | 作用 | 当前值 |
|---|---|---|
| `PRIMARY` | 选项主人格得分 | 3 |
| `SECONDARY` | 选项副人格得分 | 1 |
| `DUAL_RATIO` | 第二名/第一名 达到此比例即显示双重人格倾向 | 0.93（实测触发率约 25%） |

调完 `DUAL_RATIO` 跑一次 `check.js`，看「双重人格倾向出现率」是否落在 15%–35%。太低＝这个功能白做了，太高＝人人都双人格，等于没有。

### 4.7 换配色 → `content/albums.js` 的 `palette`

每张专辑一组 `ink`（主色）/ `accent`（辅色），会同时驱动首页卡片、结果页标题色、海报主色块。日期采用 90–00 年代唱片印刷的沉色，不建议用高饱和渐变。

## 五、每次改动后必跑

```bash
node tools/check.js    # 内容、字段、八维覆盖、可达性、结果分布、稳定性
node tools/smoke.js    # 全流程跑一遍，确认不报错
```

`check.js` 会报这些情况：字段缺失、推荐曲名查无此歌、题目选项不合法、八维分布失衡、某个人格永远测不出来、单题影响力过大。

## 六、内容原则与边界

- **只写可查证的事实**：发行日期、厂牌、曲目、已公开的合作者与奖项。
- **区分三层**：事实 / 乐评观点 / 本站解读。含争议的部分（如《太美丽》2006 年的口碑撕裂、《69乐章》的分歧)会被明确写成「另一种声音」。
- **不用专辑封面、歌词全文与音乐文件**，视觉全部为原创排版设计。
- **不按播放量排序曲目**，建议聆听刻意包含非主打、demo 与遗珠。
- 若发现事实错误，改 `content/albums.js` 即可，欢迎更正。
